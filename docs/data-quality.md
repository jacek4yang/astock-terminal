# 数据血缘、实时性与跨源质量门禁

## 目标

每一个可用于估值、回测或投资研究的数字，都要能够回答：来自哪里、代表哪个时点、何时获取、使用哪个解析器和结构版本、采用什么单位/币种/复权/财务口径、是否缺失或冲突。缺少这些信息时，系统保留原值但降低置信度；硬过期、口径不兼容或未解决的跨源冲突会阻止确定性计算和高置信结论。

## 统一数据信封

`astock_core::DataEnvelope<T>` 包含：

- 数据集、来源、原始地址；
- 事件时间、数据时点、发布时间、获取时间；
- 解析器版本、结构版本、修订号、许可说明；
- 单位、币种、复权口径、合并/母公司/每股/总额口径；
- 可追加的字段级质量标记。

存储层把信封投影到 `field_lineage_records`。字段下钻读取这张追加式审计表，不依赖内存中的临时结果。

## 数据集实时性规则

不同数据集不共用一个 TTL。实时行情、分时、日/周/月线、资金流、财务报表、估值、公告、资讯、图谱、宏观、回测和搜索线索各自声明预期更新间隔、陈旧阈值、硬过期阈值与交易时段规则。实时行情在非交易时段不会因为停止跳动而立即误报陈旧；超过硬过期阈值仍会阻断。

质量结论分为：

- `fresh`：在声明时效范围内；
- `stale`：可以展示和作为中等置信参考，不得升级为高置信；
- `expired`：硬过期，禁止确定性计算；
- `blocking quality flag`：单位、币种、复权、财务口径不兼容或跨源冲突，禁止确定性计算。

## 跨源对账

实时行情校验并发读取通达信与东方财富，比较最新价、开高低昨收、成交量、成交额、涨跌额、涨跌幅和换手率。估值校验并发利用东方财富、已配置的聚宽与 Tushare。聚宽“亿元”显式换算为元；Tushare“万元”已在 provider 层显式换算为元。每项比较保留双方原值、单位、币种、时点、绝对/相对偏差和容差，不会静默选择更有利的数字。

缺少第二来源时返回明确限制，不使用缓存、推算或零值伪装双源校验。聚宽和 Tushare 未配置属于可解释的能力缺失，不会隐藏。

## 运行观测与连续报告

`data_quality_observations` 记录 Agent 工具、缓存命中、普通行情调用和显式校验的成功、失败、延迟、缺失、冲突与实时性。设置页只读取本地观测，不为美化健康状态主动访问上游。

连续健康报告声明真实样本数量、最早/最晚观测和覆盖秒数。若运行时间尚不足 24 小时、7 天或 30 天，报告明确写出覆盖不足，不补造历史数据。SQLite 查询当前最多读取最近 5000 条观测；达到高调用量时报告的覆盖范围会如实缩短。

## Agent 门禁

所有 Agent 工具摘要统一附带 `data_quality`。缓存命中会按当前时间重新计算年龄，不能沿用写入缓存时的“新鲜”判断。工具失败也产生质量观测。估值未在同一工具内完成独立对账、回测输入未逐字段跨源复核时，置信上限固定下调。

最终答案由确定性门禁再次扫描全部工具结果：存在硬过期或阻断冲突时，自动追加“不得用于明确买卖结论”；仅有陈旧、缺失或未复核时，自动追加“置信度已下调”。该文字不依赖模型自觉，模型无法绕过。

## 故障注入与验证

核心测试覆盖：

- 实时行情硬过期；
- 单位、币种、复权和财务口径同时错配；
- 数值偏差超过容差；
- 每股字段缺少币种或错误使用总额口径；
- 质量观测、字段血缘和阻断对账在重启后仍存在；
- Agent 缓存结果按当前时点重新判定并写入缓存命中观测；
- 行情价格的容差内一致与超限冲突。

真实网络校验只能报告当次实际上游结果；CI 的确定性测试不把外网成功作为通过条件。
