# 双时间关系图谱与历史快照

## 两个时间轴

- `valid_from / valid_to`：关系在现实业务中的有效区间。例如 2024 年报披露的客户占比属于 2024 报告期，不能用软件启动时间代替。
- `recorded_at / superseded_at`：该修订何时进入系统、何时被后续更正替代。迟到材料即使描述更早业务期，也只能从实际入库之后对系统可见。
- `observed_at`：来源首次公开或被观测的时间；用于证据年龄和置信衰减。

`graph_as_of(business_time, knowledge_time)` 同时约束两个时间轴。历史分析不得省略 `knowledge_time`，否则后来发现的关系可能倒灌到过去。

## 不可变结构

`graph_edge_identities` 保存稳定身份：主体、客体、关系、产品范围、地区范围。`graph_edge_revisions` 保存不可变修订：报告期、占比、权重、证据版本、来源、状态和两个时间轴。同一供应关系可拥有多个报告期和不同占比，不会覆盖历史。

状态包括：

- `candidate`：候选，不能进入有效图。
- `verified / active`：已核验或有效。
- `stale`：已超过来源对应的复核周期，保留但明确降级。
- `contradicted / expired / revoked`：存在反方证据、业务到期或人工撤销，不进入有效图。

年报、招股书、调研、招投标、合同、专利、监管批文和产能披露分别配置复核周期与证据半衰期。到期只产生待复核状态和衰减，不删除原始修订。

## 可重复快照

快照 ID 由业务时间、知悉时间、选中的 revision ID 和实体合并 revision ID 确定性计算。同样输入必须得到同一 `graph-snapshot:*`；首次生成会写入 `graph_snapshot_records`，之后可按 ID 完整重放。如果发生非法回溯写入导致结果变化，重放会拒绝而不是悄悄返回另一张图。

实体合并单独记录在 `graph_entity_merges`。历史 revision 仍保留原主体，快照投影同时返回 `original_src/original_dst` 和合并后的节点。

## 回测防穿越

事件回测输入必须携带 `graph_snapshot_id` 和 `graph_knowledge_time`。快照知悉时间晚于事件可用时间时，`news_events_for_session` 返回硬错误。Agent 历史研究必须调用 `query_graph_as_of` 并在结论中引用快照 ID。

## 桌面端

“图谱分析 → 历史图谱与时间线”提供：

- 业务有效时间与系统知悉时间两个滑块；
- 当前截面的有效、待复核和被状态门禁排除数量；
- “当时所知”和后续知识截面的新增、撤销、变化差异；
- 点击关系展开全部材料版本、报告期、占比、来源、记录/替代时间、复核时间和置信半衰期；
- 可复制的确定性快照 ID。

## 迁移

迁移 v18 将旧 `graph_edges` 投影复制为初始 identity/revision。旧种子把首次启动时间误写为业务开始时间；迁移检测与创建时间相差不超过五秒的值，并改为 `0`（未知/长期有效），不会伪造报告期。旧表继续作为当前投影供兼容代码使用，历史查询只以新修订表为准。
