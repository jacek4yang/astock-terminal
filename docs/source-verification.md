# 原始来源核验与字段级证据

本文对应 GitHub Issue #9。外部搜索、快讯标题和摘要只负责发现网址，不能直接成为投资事实。事实链路固定为：发现 URL → 受控读取原文 → 保存不可变版本 → 解析段落/页码 → 抽取字段原值 → Agent 引用版本与事实编号。

## 来源优先级

1. 交易所、监管机构、政府统计等一级来源；
2. 公司正式披露；
3. 授权媒体；
4. 聚合快讯；
5. 社交线索与未分类页面。

可靠性、独立性和新鲜度评分仅用于检索排序。评分不能证明正文内容，也不能覆盖精确文档证据。重大新闻回答若没有一级来源版本，必须明确显示“一级来源原文未核验”。

## 获取与存储

`fetch_source_document` 复用统一的 SSRF、DNS 重绑定、重定向、MIME、响应大小和超时安全边界，支持 HTML、JSON、纯文本、XML 与 PDF/正式附件。页面原始字节只为可公开保存的一级来源生成 gzip 快照；解析结果写入 SQLite：

- `research_source_documents`：规范化 URL、来源层级、访问状态和失败原因；
- `research_source_versions`：内容哈希、解析器版本、抓取时间和不可变修订链；
- `source_document_segments`：页码、段落、选择器、全局 span 和文本哈希；
- `source_fact_evidence`：金额、比例、日期、产能等原值、原单位、标准化值与精确位置；
- `source_fetch_observations`：每次成功或失败读取的诊断；
- `agent_source_evidence_refs`：Agent 结论到来源版本/事实编号的引用。

登录、付费墙、robots、纯动态壳、网络失败和不支持的附件均记录为 `unverified`，不使用搜索摘要补全文字。来源修订以新版本追加，并通过 `supersedes_version_id` 指向旧版，永不原地覆盖。

## 冲突与界面

`compare_source_evidence` 按字段比较 2–10 个不可变版本。不同原值、原单位、时点和位置全部保留，不按多数票或对投资更有利的方向自动覆盖。设置页“原始来源核验与字段级证据”支持：

- 手动读取公开 URL；
- 展开来源、版本、评分、原文段落和字段证据；
- 查看 PDF 页码、网页段落、span、抓取时间、内容指纹；
- 复制单条证据、完整证据包或失败诊断；
- 勾选多个版本逐字段核对冲突。

## 回归夹具

`crates/source-verification/tests/fixtures` 包含 HTML 公告、公告修订、JSON、PDF 表格行、动态页面和不可访问页面。测试验证原单位、页码、修订链、冲突、未核验状态和 Agent 引用持久化。

## 已知限制

- 扫描型 PDF/OCR 尚未支持；无文本层的 PDF 会保留版本但可能没有可抽取字段。
- JavaScript 动态页面不会在应用内执行脚本，需改用其公开 JSON 接口或正式附件。
- 字段抽取是确定性规则，不覆盖所有行业表述；缺失字段仍可在原文分段中人工核对。
- 来源分类需持续维护；未知公司域名在确认前不会自动升级为一级来源。
