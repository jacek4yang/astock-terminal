# AStock Terminal v6.0.0 migration and known limits

## Data adoption

- New installations use `%LOCALAPPDATA%\com.astock.terminal`.
- Existing `%APPDATA%\astock-terminal` or a configured `data_dir` is adopted in place. Large SQLite and Parquet stores are not silently copied or deleted.
- Database upgrades first create and integrity-check an online backup, then apply schema changes transactionally.
- The explicit D-drive migration copies SQLite through the backup API, verifies integrity and the Parquet manifest, atomically switches the active pointer, and retains the old copy for rollback.
- Historical research and reports remain available through the read-only Legacy Research Archive. The v5 workspace layout, local UI preferences and chat presentation are intentionally not migrated.

## Credentials

- Credentials exposed before this release must be revoked and replaced before live acceptance.
- Fresh MiniMax Plus, JoinQuant and optional provider credentials are stored only in Windows Credential Manager. They are not imported from chat, command-line arguments, environment variables, SQLite, logs or renderer state.

## Known limits

- v6.0.0 supports Windows x64 only. Linux automation covers headless and formal checks, not the desktop application.
- The application creates research and manually reviewed investment plans only. It has no broker connection, order submission, automatic execution or unattended trading.
- External provider availability, entitlement and upstream correctness are trusted boundaries. Missing, stale, conflicting or single-source material data is shown explicitly and may block report publication.
- GitHub-hosted Actions were unavailable because of the repository billing/spending restriction. The immutable local report contains the executed gates and classifications.
