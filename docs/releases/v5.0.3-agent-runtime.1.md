# v5.0.3-agent-runtime.1

Agent Runtime robustness prerelease for the 5.0.3 application line.

## Changes

- Added MiniMax SSE first-chunk and idle watchdogs.
- Added safe pre-commit stream reconstruction without replaying committed visible text or tool calls.
- Added a durable runtime supervisor that clears truncated drafts and resumes from the latest SQLite checkpoint.
- Added bounded transient retry and persistent suspension after the retry ceiling.
- Added canonical tool cache keys for typed symbol, period and adjustment fields while preserving opaque strings.
- Added per-key single-flight for concurrent successful and failed tool calls.
- Added generous tool-class deadlock budgets so one stalled source cannot block an entire Agent run.
- Added deterministic unit tests and a runtime fault matrix.
- Replaced the initially unrecorded DashMap dependency with a short-held standard-library `Mutex<HashMap>` single-flight index, restoring `Cargo.lock` compatibility for `--locked` release builds.

## Release gates

The GitHub prerelease is created only after all of the following complete successfully in the dedicated release workflow:

- RustSec dependency audit.
- Versioned deterministic research evaluation gate.
- Rust formatting, workspace tests, Clippy with warnings denied, and desktop application check.
- Frontend dependency lockfile install, production build, and test suite.
- Windows Tauri build producing both MSI and NSIS installers from the immutable source commit.
- Build metadata proving the source commit and platform.
- SHA-256 verification of every uploaded installer and metadata file.

## Execution paths

The preferred path is the gated `release-agent-runtime` GitHub Actions workflow. A Windows fallback publisher is also included for periods when GitHub-hosted runners cannot start:

```powershell
# Validate and package without changing GitHub
pwsh -File .\scripts\release-agent-runtime.ps1

# Repeat all gates, then create or update the prerelease
pwsh -File .\scripts\release-agent-runtime.ps1 -Publish
```

The fallback uses an isolated detached worktree at the immutable source commit, refuses mismatched tags, and does not publish unless every audit, evaluation, test, build and checksum step succeeds.

## Packaging notes

- Assets use stable `astock-terminal-<tag>-windows-x86_64` names and include `BUILD-METADATA.txt` and `SHA256SUMS`.
- The release workflow can be executed only from `main`; a manual dispatch from another branch cannot publish.
- The workflow and fallback script refuse to reuse the tag when it points to any commit other than the immutable source commit.
- The workflow does not apply a Windows code-signing certificate. Verify downloaded assets against `SHA256SUMS`; Windows may display an unknown-publisher warning.
