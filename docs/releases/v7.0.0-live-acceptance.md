# v7.0.0 live acceptance results

Recorded from real runs against the live MiniMax API and live market upstreams,
with credentials installed through `astock credentials set`. No value was printed,
logged or committed.

## What live testing confirmed working

**Provider integration.** Model discovery returned 8 real models
(`MiniMax-M3`, `MiniMax-M2.7`, `MiniMax-M2.7-highspeed`, `MiniMax-M2.5` and
others). Quota returned real per-model windows and remaining percentages. Both
went through the OS credential store, and `astock doctor` reports presence
without revealing a value.

**Tool execution against live data.** A research task drove 9 to 23 tool calls
per run across `get_quote`, `get_kline`, `get_fundamentals`, `research_news`,
`prepare_market_research`, `get_market_regime` and `research_securities`, with
real evidence registered.

**Degradation is honest.** When the Eastmoney large-page snapshot returned 100 of
an expected 5,904 rows, the Engine logged the shortfall and fell back to complete
pagination rather than treating a partial snapshot as success.

**Failure handling is fail-closed.** A provider stream that closed before its
termination marker produced a `suspended` task, not a completed one, with the
message that it can be safely retried from the persisted task. The session
remained listed as `suspended` with its evidence intact. The runtime never
published a partial answer as a finished report.

## Blocker fixed as a result

The first run failed with `MiniMax API 400: context window exceeds limit` after 13
successful tool calls, because full tool results were placed in the model
conversation with only a 2 MiB storage bound. Model-context and storage budgets
are now separate. Re-running the same prompt raised tool success from 8-of-13 to
9-of-9 and removed the rejection.

## Blockers still open, and why v7.0.0 is not tagged

**The Agent cannot currently complete a substantial research task.** On the
worked example it ran 23 tool calls and generated a full report, then produced
**1,178 blocking verification findings** and exhausted the 16-round limit without
publishing. The findings fall into classes:

| Class | Observed | Reading |
| --- | --- | --- |
| `numeric_claim_without_evidence:line_N` | ~80 distinct lines | the model writes figures without attaching an evidence identifier |
| `numeric_claim_not_reproduced:line_N:VALUE` | ~90 distinct values | figures the deterministic verifier could not reproduce |
| `invalid_or_conflicting_evidence_id:evf_…` | several hundred | cited identifiers the verifier rejects |
| `unknown_evidence_id:计算-BPS`, `财报口径-EPS-2024` | 13 | the model **invented its own citation labels** instead of using `evf_` identifiers |
| `evidence_time_missing:evf_…` | 12 | registered observations lacking a timestamp |

The runtime is behaving correctly: publishing a report with blocking findings is
forbidden, so it refuses. The product problem is that the model cannot satisfy the
verifier, so no report is ever published.

**A simple query can end in an empty model turn.** Asking only for the latest
price completed 10 tool calls and produced just 3 verification findings, then
failed after 12 rounds with `model returned neither visible text nor a tool call`.

These are not addressed by the context-budget fix and must not be "fixed" by
relaxing the verifier. Weakening the evidence gate to make reports publish would
invert the product's first priority, financial correctness, and would make the
Agent confidently emit unverified numbers — worse than emitting nothing. The real
work is on the citation side: making the model reliably attach valid `evf_`
identifiers, and making unreproducible figures either computed deterministically
through the Engine or stated as estimates.

## Root-cause matrix

Measured against the persisted effects and event stream of the failing run, not
inferred. 33 succeeded tool effects contributed 7,054 evidence-fact rows covering
6,578 distinct identifiers; the generated report cited 37.

| Finding class | Count | Root cause | Whose defect |
| --- | --- | --- | --- |
| `invalid_or_conflicting_evidence_id` | 476 ids | The same identifier was registered twice with a different `observed_at`. In **476 of 476 cases the differing field was `observed_at` alone** — `path`, `value` and `source` were identical. Example: `/adjustment` = `"qfq"` from `joinquant`, registered 30 seconds apart. Only **3 of the 476** were cited by the report. | ours |
| `evidence_time_missing` | 31 facts | **All 31 have `source: astock-compute`** — deterministic calculation outputs, with leaf paths `kind`, `value`, `fuel_used`, `program_sha256`. A derived calculation has no observation time; requiring one conflates calculation provenance with observation provenance. | ours |
| `numeric_claim_without_evidence` | 121 lines | **101 genuine** — the model wrote financial figures with no citation. **20 verifier false positives**: stock codes (`601899`), dates (`2026-08-26`), Markdown section numbering (`## 第一步`), and period labels (`6个月`) are counted as unsupported financial claims. | 101 model / 20 ours |
| `numeric_claim_not_reproduced` | ~90 values | The model performed material arithmetic in prose — market capitalisation as `2.659亿股 × 34.47`, a `-32.4%` drawdown, EPS — rather than through a deterministic calculation whose result could be cited. | model, needs a mechanism |
| `unknown_evidence_id` | 13 labels | The model invented its own citation namespace (`计算-BPS`, `财报口径-EPS-2024`) because citations are hand-formatted free text with nothing constraining the identifier space. | model, needs a mechanism |

Two conclusions follow. First, **over 500 of the findings were ours, not the
model's**: retrieval-time drift misread as a value conflict, calculation outputs
judged against observation semantics, and a numeric extractor that cannot tell a
stock code from a quantity. Second, the residual ~200 model-side findings are
concentrated in exactly two behaviours — uncited figures and prose arithmetic —
which is what a structured claim contract with explicit numeric provenance is for.

Fixing the first group is a correctness fix and does not relax any gate: a report
citing a genuinely conflicting fact, or asserting an unsupported quantity, still
fails closed.

## Measured effect of the fixes

Same prompt, same provider, after the verifier-correctness and tool-recoverability
fixes. Blocking findings fell from **1,178 to 123**, a 90% reduction, and three
classes were eliminated outright.

| Class | Before | After |
| --- | ---: | ---: |
| `invalid_or_conflicting_evidence_id` | several hundred | **0** |
| `unknown_evidence_id` (invented labels) | 13 | **0** |
| `evidence_time_missing` | 12 | **0** |
| `numeric_claim_not_reproduced` | ~90 | 82 |
| `numeric_claim_without_evidence` | 121 | 41 |

The run also survived a class of failure that previously destroyed it. An earlier
attempt died on `invalid arguments for tool run_financial_calculation: EOF while
parsing an object at line 1 column 3559` — a truncated argument object — after
eight tools had already succeeded. Malformed arguments on a *registered* tool are
now reported back as a failure of that one call, so the model can re-send a smaller
payload; 11 tool failures occurred in this run and it continued through all of them
to verification. An unknown *tool name* remains fatal, because a call outside the
closed registry is an attempted capability escape rather than a formatting slip.

## What still blocks publication

The residual 123 findings are entirely the two model-side behaviours, and they are
the same two the root-cause matrix predicted would remain:

- **41 `numeric_claim_without_evidence`** — figures written into prose with no
  citation attached to that line.
- **82 `numeric_claim_not_reproduced`** — derived quantities computed in prose
  (market capitalisation from shares × price, percentage moves, per-share figures)
  rather than through a deterministic calculation whose result could be cited.

Neither is a verifier defect. Both follow from the same architectural cause: the
model writes free-form Markdown and hand-formats citations, so attaching valid
provenance to every material figure is entirely a matter of model discipline. The
remedy is the structured claim contract — the model submits claims carrying
explicit evidence identifiers and numeric provenance, the Runtime validates and
renders the citation syntax, and derived values are required to come from a cited
deterministic calculation or be declared an estimate or scenario.

## Structured finalization is now the publication path

The contract described above was defined, schema'd and unit-tested, but it was
never reachable. `submit_report` and `search_evidence` were registered with
`handler = Runtime` and an empty `engine_kind`, and the runtime loop contained no
reference to either — so both calls fell through to Engine dispatch with an empty
request kind and could only fail, while the system prompt instructed the model to
"publish only through submit_report". `validate_draft` and `render` were complete
and never called. That is now implemented.

```text
research → evidence catalog → search_evidence → deterministic calculation
        → submit_report → validate_draft → render → independent verifier → publish
```

**The free-form path is gone, not deprecated.** A text-only model turn is no
longer a publication candidate. It used to go straight to the verifier, which is
what forced the model to hand-format `【E:evf_…】` into investor-facing prose —
leaking machine identity into the product and leaving provenance to its formatting
discipline. A prose turn now returns an instruction to submit through the
contract, bounded by the finalization budget, and a task that only ever produces
prose fails closed.

**Evidence discovery is real and bounded.** The catalog is built from the durable
tool result rather than the bounded model projection, so a truncated context never
means lost provenance. A fact's security is attributed from the enclosing bundle
(`/securities/0/symbol` is a sibling field, not part of the fact's path), which is
what makes the contract's task-scope check meaningful and what lets a citation
read `公司公告 · 半年度报告` instead of a bare source name. Search results are
capped at 50 rows with capped rendered values, ranked deterministically, and a
search that matches nothing returns the sources and field fragments the catalog
actually holds — the alternative, a bare empty list, is what drives a model to
invent an identifier.

**Repair is addressed to a claim.** A verifier finding of
`numeric_claim_not_reproduced:line_3:21.5` is resolved through the line index of
the form the verifier read, so the model is told which claim to fix and which
figure failed, with a specific action. The previous behaviour returned 1,178
textual findings and asked for a full rewrite; that loop never converged.

**Budgets are per phase.** Research rounds and finalization attempts are counted
separately, and an identical resubmission is detected: the first repeat gets a
sharper instruction, a second ends finalization, because spending the remaining
budget on a fixed point cannot help. Exhausting either budget refuses to publish.

### One verifier defect fixed on the way

The verifier's number pattern matches no sign, so a negative quantity could never
be reproduced: a maximum drawdown registered as `-0.0999` was extracted from the
report as `0.0999`, compared against `-0.0999`, and reported as
`numeric_claim_not_reproduced`. Every signed figure a deterministic calculation
produces hit this — which meant the Engine's own arithmetic could not be cited.

A leading `-` now counts as a sign only when what precedes it is not part of a
number, so `20-30 元` stays two positive quantities while `max_drawdown=-0.0999`
and `涨跌幅 -3.5%` are negative. This does not relax the gate: an unsigned claim is
still compared unsigned, so a claim asserting a 3.5% gain is still refused against
evidence of a 3.5% loss.

### Deterministic evidence for the path

`crates/agent-runtime/tests/finalization.rs` pins each closed route: a well-shaped
but absent identifier, an estimate standing in for a computable quantity, evidence
belonging to another security, a verifier refusal, an exhausted budget, an
identical resubmission, and free-form prose. Two facts are worth separating from
the rest:

- **A runtime-served tool never reaches the Engine.** Asserted on the dispatch log,
  not on the type alone.
- **The renderer's canonical form satisfies the real verifier.**
  `a_structured_report_passes_the_real_engine_verifier_and_publishes` runs a real
  embedded Engine on a temporary directory, computes real calculation evidence
  through the fuel-metered calculation path, submits a structured draft, and
  publishes with **zero blocking findings**. No provider quota is consumed and no
  network is used.

What remains unproven is live behaviour: whether the model reliably produces a
draft that satisfies the contract on the first or second attempt against the real
provider. That is the next measurement, and it is a model-behaviour question now
rather than an architectural one.

### Known calibration question, deliberately not changed here

`RuntimeTask::verification_spec` sets `evidence_requirement = "strict"` for every
task, which requires at least 8 distinct citations regardless of research depth.
For `分析紫金矿业当前投资价值` that is right. For `紫金矿业最新价格是多少？` it is
probably mis-calibrated — `depth = fast` arguably maps to the verifier's existing
`standard` requirement of 4. Changing it is a gate calibration decision, so it is
recorded here rather than folded into an implementation change.

## Live acceptance A: a simple factual question now publishes

`astock ask --depth fast --symbol 601899 '紫金矿业最新价格是多少？'` against the live
MiniMax API and live market upstreams. **Exit 0, zero blocking verifier findings,
report published.**

| | Free-form baseline | First structured run | After the evidence-registry fix |
| --- | ---: | ---: | ---: |
| Blocking findings at the end | 123 | 2 | **0** |
| Tool calls | 10 | 21 | **4** |
| Independent verifications | 1 | 3 | **1** |
| `submit_report` attempts | — | 4 (exhausted) | 2 |
| Distinct citations in the report | — | 10 | 11 |

The two intermediate failures were both `undeclared_number_in_statement`, caught by
the contract before the verifier ran, repaired in one round, and then published.

Three fixes account for the difference between 21 tool calls and 4.

**Focused tools now register citable evidence.** `market.quote`, `market.kline`,
`research.fundamentals`, `research.news` and `research.market.regime` attached no
`evidence_registry`, so the tools that answer a focused question produced nothing
citable. In the first structured run `get_quote` succeeded, the catalog stayed
empty, the model's first searches returned nothing, it invented 13 identifiers, and
the first verification saw `registry_facts=0`. It then swept the whole market
through `prepare_market_research` — 3,000 facts and a 5,904-row snapshot — to obtain
an identifier for one price. A registry is what makes an observation citable, so a
tool returning observations without one cannot support a published claim.

**Figures written into prose are refused at validation.** Both residual findings of
the first run were of this kind: `约 79.87 亿元` as a rounded restatement of the
cited `7,987,376,586`, and `单手(100 股)` as a lot size. The canonical form places a
claim's statement and its citations on one line, so a figure in the prose is checked
against the evidence the claim named exactly as a declared number is. The rule is
the verifier's own — `financial_numerals` and `ReportNumeral::supported_by` are
shared, so validation is exactly as permissive as verification rather than a second,
drifting implementation.

**Declared numbers reach the reader.** `render_markdown` emitted only claim prose, so
a figure living in `numeric_items` — the only place a figure carries provenance —
never reached the page. Numbers now render with unit, provenance label, derivation
for a calculation, and citation numbers.

### What the published report looks like

The reader sees numbered citations with human labels and no `evf_` identifier, every
figure marked `实测数据` with its citation, the data timestamp stated, and the
snapshot's limitations declared — single source, not a closing price, no
cross-terminal comparison. That is the shape the product is supposed to produce.

### What the moderate case cost to learn, and what it taught

The balanced case was run **32 times** across this work. It is the most expensive
measurement in the project and it produced most of the fixes above, so the sequence is
worth recording rather than summarising as a pass rate.

Every failure fell into one of two kinds.

**Defects in the rule, not the report.** Text that asserts no quantity was being read
as an unsupported figure, and each one needed a live run to discover: reporting
periods (`2025 全年`, `2026 中期`), lookback windows (`250 日 K 线`, `60 日均线`),
year-months (`2026-03`), Chinese counters (`命中 2 项`, `各投 ±1 票`, `21 个样本`),
distribution-ratio denominators (`每 10 股派`), inline enumerations (`1) … 2) …`), a
space before a magnitude suffix (`3490.79 亿元` parsing as `3490.79`), and a two-digit
day rule that masked the tail of `250 日` as `50 日` and left a stray `2`. All are
fixed, and all are narrowings of *what counts as a claim* — none changes how a claim is
verified.

`crates/agent-runtime/tests/live_draft_replay.rs` exists because of this. It replays 49
real submitted drafts against the rule offline, so a masking gap is now a one-second
test instead of a paid round trip.

**A contract the model would not follow.** The brief asked for a stronger invariant —
financial figures cannot appear freely in statement text — to be implemented properly
and measured live. It was, in two forms:

| Contract | Live moderate result |
| --- | --- |
| Conditional: a figure is allowed if the same claim declares it | published 2 of 8 |
| Absolute: no figure in any prose field | published 0 of 11 |
| Absolute plus `{label}` references resolving everywhere | published 1 of 7 |
| Backed: every printed figure declared or cited, references preferred | measurement incomplete — quota |

The absolute rule was satisfiable in principle and the model would not comply: it wrote
prose as an analyst does, producing 22 to 44 refusals per run. Under repair pressure it
then *deleted* figures, tripping `report_contains_no_verifiable_numeric_claims`. The
measurement said no, so the rule was returned to the one the verifier actually enforces:
every printed figure must be backed by a declaration or by cited evidence.

**What was kept from the attempt.** Two things, both real:

- `{label}` references. The model writes `收盘价{收盘价}` and declares that item; the
  runtime substitutes the verified value into both the reader's prose and the verifier
  form. One numeric truth, presented by the runtime — which is what the brief asked for
  — and the model adopted it readily once it existed.
- Free-text coverage. The verifier reads only the title, the section headings and the
  claim lines, so a figure in `executive_summary`, `overall_uncertainty`, `limitations`,
  `assumptions` or `uncertainty` was **published with no check at all**. Those fields are
  now checked, and the ones that reference a figure are emitted into the verifier form.
  That hole existed before this work and is closed regardless of the rule's strictness.

### Convergence is real; the budget was set below it

Findings per submission, read from durable event logs rather than inferred:

```text
40 → 10 → 2 → 2   published
40 → 18 → 2       budget exhausted at 6
40 → 16           budget exhausted at 6
```

The repair loop converges. Two things were cutting it short, and both are fixed: the
repair response listed 24 affected claims when more were affected, so the omitted ones
resurfaced a round later and consumed budget; and the finalization budget of 6 sat
exactly at the edge of a trajectory that needs four or five submissions to become
publishable and one more to finish. The budget is now 8, justified by that measurement,
and identical-resubmission detection still ends a loop that is not converging regardless
of remaining budget.

### External blocker: provider quota

Further live measurement is blocked. The MiniMax rolling interval is exhausted:

```text
general   interval_status=2   interval_left=0.0%   weekly_left=65.0%   resets_in=123min
```

The runtime handled it exactly as the architecture requires, which is itself evidence:

### Still unmeasured

Cases B and D through J of the live sequence — explanation reuse, deep research,

## Live acceptance C: a moderate report now publishes

`astock ask --depth balanced --symbol 601899 '简单分析紫金矿业当前估值、趋势和主要风险。'`
**Exit 0. The independent verifier returned `passed=true` with no findings**, over 20
distinct citations and 25 checked numeric claims.

The case was run five times as fixes landed. Each of the first four exposed a
*distinct* real defect rather than repeating one, and each is fixed:

| Run | Outcome | Defect exposed |
| --- | --- | --- |
| 1 | round limit, 11 submissions against a budget of 6 | A draft `serde` could not decode bypassed the finalization ledger entirely — the repair loop was unbounded |
| 2 | round limit, 37 prose-figure findings | Reporting-period labels (`2025 全年`, `2026Q1 末`, `近 3 年`) counted as financial figures; the round ceiling pre-empted the phase budgets |
| 3 | budget exhausted at decode | `invalid type: map, expected a string` named no field — six identical failures on `limitations` entries wrapped in objects |
| 4 | budget exhausted at validation | Declared values were never checked against their own evidence; fundamentals evidence carried no observation time; a calculation claim could not state its inputs |
| 5 | **published, zero blocking findings** | — |
| 6 | budget exhausted at validation | Lookback windows (`250 日 K 线`, `60 日均线`) and inline enumerations (`1) … 2) …`) counted as financial figures |
| 7 | budget exhausted at decode | The schema listed every provenance field as an optional sibling, so nothing stated that `calculated` requires `calculation_evidence_id` — the same missing field six times |
| 7b | killed at round 3 | A misnamed tool (`search_news` for `research_news`) was fatal, discarding eight successful tool calls |

The contract absorbed the remaining friction where it is cheap: 43 problems were
raised and repaired at validation across six submissions, and the single independent
verification that ran passed outright. That is the intended shape — the expensive
gate should be reached only by a draft that already satisfies the contract.

The bounded verifier projection is visible in the same record: the context carried
**20 facts**, the ones the report cites, rather than the thousands of rows the
research produced.

### Report quality items, not correctness

- A claim listed in more than one section renders more than once. The published
  report repeats its quote claim under both 估值 and 趋势. Validation requires every
  claim to appear in at least one section and does not forbid duplication; whether it
  should is a presentation decision.
- Some declared values carry full source precision (`PB(MRQ) 4.55142037 倍`). Rounding
  for display cannot be done in the statement — a rounded figure is a different,
  unverifiable figure — so it belongs in the renderer, with the exact value retained
  for verification.

### Repeatability, measured

| Case | Runs | Published | Notes |
| --- | ---: | ---: | --- |
| A, simple factual | 2 | **2** | 2–4 tool calls, one verification, zero blocking findings each time |
| C, moderate three-part analysis | 12 | 2 | Seven of the failures each exposed a distinct defect, all fixed; the last three share one cause. Early runs were against progressively older code, so this is not a fixed-code success rate |

Case A is repeatable. **Case C is not.** Counting only the three runs against the
final code, it published once. The reason for the failures is now singular rather
than varied: `undeclared_number_in_statement` accounted for 49 of 75 and 34 of 40 findings
in the two most recent failures, with everything else in single digits.

### Why the remaining rule is hard to satisfy, and what would fix it

The rule is conditional: *a figure may appear in a statement only if the same claim
also declares it, or cites evidence containing it*. A model writing
`当前股价 34.57 元,较前收 34.47 元上涨 0.10 元` must declare all three. It reliably
declares the headline figures and drops the incidental ones — a change, a range
endpoint, a derived percentage — and each omission is a refusal.

Relaxing the rule is not available: every relaxation admits a figure that nothing
verifies into a published report, which inverts the product's first priority.

The promising direction is the opposite, and it is **stricter**: forbid a financial
figure in a statement outright and let the renderer present every number from
`numeric_items`. An absolute rule is mechanically checkable by the model before it
submits ("write no digit in a statement"), whereas a conditional rule requires it to
cross-check each figure against its own declarations. The model already writes in this
style when pushed — `具体数值见下方` appeared spontaneously in one run — and the
renderer has emitted numbers with their provenance since this change set.

That is a behavioural change to the contract with a prose-style cost, so it is
recorded as a recommendation rather than applied on the strength of a few runs. It
needs its own live measurement.

### Still unmeasured

Cases B and D through J — explanation reuse, deep research, scenario, opportunity

## External blocker: the MoonBit toolchain pin is not version-addressed

`moonbit-agent` fails on `main` and on every branch, at
`Install pinned MoonBit toolchain`:

```text
moonbit-linux-x86_64-0.1.20260824-dae026a.tar.gz: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
```

The workflow downloads
`https://cli.moonbitlang.com/binaries/latest/moonbit-linux-x86_64.tar.gz` — a moving
reference — and checks it against the SHA-256 of one specific build, then asserts
`moon 0.1.20260824 (dae026a`. Those two are contradictory: the checksum breaks on
every upstream nightly publication. The pin is working correctly; the URL is wrong.

This is not a defect in the Rust work and must not be "fixed" by updating the
recorded checksum. Doing so would accept an unverified binary and defeat the pin,
and the version assertion immediately below it would then fail as well, so the fix
would have to silently adopt an untested toolchain version.

Two candidate resolutions, both requiring a decision:

1. **Version-address the download.** Fetch an immutable, version-named artifact so
   the checksum is stable. **This appears not to be available from the vendor.**
   `moonbitlang/moonbit-compiler` publishes only `moonbit-wasm.tar.gz` on its GitHub
   releases — no versioned `moonbit-linux-x86_64.tar.gz` — and `moonbitlang/core`
   publishes no releases at all. The CDN `latest` path looks like the only channel for
   the Linux toolchain binary, which means a pinned checksum and this URL cannot both
   hold. Confirming that requires reaching `cli.moonbitlang.com`, which the
   development host cannot: TLS connections to it are reset.
2. **Scope the job to what it guards.** `app-moon` is archived specification
   material, not the production runtime, so a green Rust release currently depends on
   a moving third-party nightly download. Making that job non-blocking is defensible
   for exactly that reason, but it is a release-gate policy change and needs an owner.

A third option, if the archived MoonBit checks are to stay blocking: mirror a verified
toolchain into infrastructure the project controls and pin that, so re-pinning becomes
a deliberate, reviewed act rather than a race with upstream publication.

Until one is chosen, every pull request carries one red required check for a reason
unrelated to its contents.

## Prompt and control-plane convergence

The system prompt still carried an instruction that contradicted the structured
contract:

> 每个关键事实和数值使用 Engine 返回的 evidence_registry 中的标识，格式为【E:evf_xxx】

That told the model to hand-format investor-facing citations, which is now the
renderer's job. Leaving it in place is the most plausible proximate cause of the 13
invented citation labels seen live: the model was being asked to author a citation
namespace by hand, and when it lacked an identifier it produced a plausible-looking
one such as `计算-BPS`.

### Language architecture

| Layer | Language | Reason |
| --- | --- | --- |
| System prompt, tool descriptions, repair diagnostics, schema terms | English | Machine control surface, re-sent every round, sits in the cacheable prefix |
| Source evidence | Original | Chinese disclosures stay Chinese; nothing is translated to make the control plane uniform |
| All user-visible output | Simplified Chinese | Carried explicitly as `output_language=zh-CN` rather than inferred |

The reply language is passed as a field, not left to the model to deduce from a
mostly-English prompt. That kind of implicit coupling breaks quietly.

### What was removed rather than translated

The rewrite is not a translation. Rules the type system already enforces were
deleted rather than restated, because prompt tokens spent on them buy nothing and
drift out of date:

- evidence identifier shape — enforced by the `submit_report` schema pattern;
- claim/provenance compatibility — enforced by `ClaimKind::permits`;
- bounds on claims, statements and evidence lists — enforced by the schema;
- citation formatting — owned by the renderer;
- unknown-tool rejection — fail-closed in the runtime.

What remains is the set of rules that genuinely need model cooperation: which
evidence to seek, which claim kind an assertion actually is, when to compute rather
than assert, graph and backtest scope honesty, and the trading boundary.

### Measured size change

By a CJK-aware proxy — one token per Chinese character, four characters per token
for English — the static prompt moved from roughly **712 to 595 tokens, about 16%
smaller**, while covering the same enforceable ground plus the finalization contract.

This is an estimate from character counts, not a figure read from the API. No claim
is made here that English improves model reasoning; the measurable properties are
size, byte-stability of the cacheable prefix, and the removal of the contradiction.
A live A/B against real usage fields is still outstanding.

### Cache layout

The static control plane is byte-identical across rounds and tasks; only a
four-line `TASK` block varies and it is placed last. A test asserts the prefix is
identical for two different tasks, so a refactor cannot silently make it
task-dependent.

### Reasoning policy

The prompt does not dictate a reasoning language or ask the model to show its
working. Tests forbid `think step by step`, `reason in english`, `show your
reasoning` and `explain your thinking`. Effort is matched to the task in prose
guidance only; whether the current MiniMax endpoint exposes an explicit thinking
control, and whether interleaved reasoning state must be preserved across tool
turns, has not yet been measured against the live API and remains open.

## Consequence for the release

The Definition of Done requires a representative end-to-end Agent run producing a
**verified** report. That does not currently happen against the live provider, so
`v7.0.0` is not tagged. Tagging now would ship an Agent that cannot finish the
task the product exists to perform.

What *is* ready and verified is recorded separately: the architecture convergence,
the Tauri v2 desktop with working Windows NSIS and MSI installers, credential
security, migration behaviour, and the full deterministic gate suite.
