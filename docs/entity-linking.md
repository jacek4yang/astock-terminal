# 财经实体主数据、消歧与人工审核

实体链接层把文档中的证券代码、公司全称/简称/曾用名、子公司、品牌、人物、产品、行业、商品、地区和政策映射为稳定 `entity_id`。它位于不可变资讯修订之后、事件聚类和 Agent 结论之前，解决同名误配、品牌漏检、子公司误当母公司以及历史更名造成的时间错配。

## 三段式链接

1. 候选召回：从完整 SecurityMaster、产业链节点和带来源的内置基准召回代码、法定全称、简称、曾用名、英文名、品牌名及子公司名；保留原文 UTF-8 span 和所有候选。
2. 上下文消歧：代码和法定全称优先；同名候选比较行业、产品、地区等上下文词；历史名称必须落在有效区间内。
3. 规则校验：达到 0.85、拥有精确文档修订证据且不是未审核模型提议的映射才标为 `eligible_for_agent`。低置信映射进入审核队列。

LLM 只能调用候选提议入口。提议分数被强制限制在自动阈值以下，状态固定为待审核；只有用户从候选选择框确认并填写理由后才可成为已接受映射。接口也拒绝把不在该 span 候选列表中的任意实体写入结果。

## 母子公司、品牌与跨市场关系

实体与证券分开保存。子公司通过 `subsidiary_of`、品牌通过 `brand_of`、产品通过 `product_of` 关联上市主体，因此“腾势”可以解释为比亚迪旗下品牌，但原文仍显示命中的是品牌而不是上市公司本身。关系链保存来源和置信度；低于关系阈值的全球供应链线索可在 UI 中查看，但不会自动进入 Agent 投资结论。

## 可追溯数据

Schema v10 新增 `research_entities`、`research_entity_names`、`research_entity_relations`、`document_entity_links` 和 `entity_link_reviews`。每个链接保存原文起止位置、原文片段、完整候选列表、最终实体、分数、理由、链接器版本、精确证据修订和审核状态。

设置页的事件详情可以逐层展开查看命中原文、候选得分、消歧理由、关联上市主体及关系路径。待审核项使用选择框、理由和二次确认，审核前明确标注“Agent 已隔离”。

## 评测与回归

标注 fixture 位于 `crates/entity-linking/tests/fixtures/entity_linking.json`，包含代码、全称、英文名、子公司、品牌、产品、行业、商品、政策、历史更名和同名歧义。当前固定 fixture 的整体 precision、recall、F1 均为 1.00；`evaluate_fixture` 同时按实体类型拆分指标，发布阈值为 0.90/0.85/0.87。该小型 fixture 只用于确定性回归，不代表真实生产语料准确率；扩大人工标注集后必须重新报告。市场数据回归还验证只出现品牌名时仍能找到上市母公司，并保证 Agent 只收到已接受且有修订证据的映射。
