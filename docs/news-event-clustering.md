# 跨来源财经事件聚类与更正追踪

资讯档案保存的是“文档修订”，本模块在其上建立独立的“现实事件”层。财联社快讯、正式公告、媒体转载和摘要可以指向同一 `event_cluster_id`，Agent 只把该事件计作一次，但同时展示独立来源数量、证据多样性、首发来源、最新修订和每一份原始证据。

## 可解释的确定性流水线

聚类依次使用规范网址、来源编号、规范标题、SimHash、MinHash、256 维中文散列语义向量、股票代码/主体、事件动作、事实字段和事件时间。规范网址移除追踪参数并排序查询参数。合并前必须同时通过主体和时间兼容性约束；结果保存综合分、发布阈值、正向理由、保持分离的理由及各特征分数。

文档关系分为首发、转载、摘要、跟进、评论/解读、更正、撤回和重复抓取。事件发生时间与来源发布时间分开保存；首次发现晚于事件七天的内容会明确标记为“旧闻重发”，不会伪装成新催化。

## 冲突、更正和一手来源

系统按数值、主体、方向和日期检测字段级冲突。媒体转载数量不会以多数票覆盖正式披露：冲突记录会指出应优先核对的一手修订，同时保留全部互相矛盾的值。更正或撤回进入事件簇后，所有引用旧修订的 Agent 结论进入“待复核”，用户复核后显式关闭；旧报告不会被静默改写。

## 人工校正、回放与版本

人工合并和拆分要求填写理由并二次确认。成员变更、操作者、理由、时间和模型版本追加写入 `event_cluster_decisions`；历史记录不会覆盖。自动成员也保存当时使用的模型版本，升级模型后已存在的成员保持不变。

`replay_documents` 按首次发现时间和稳定文档编号排序，对同一输入快照进行无副作用离线重放，并输出输入摘要、模型版本、事件编号和逐项解释。标注 fixture 位于 `crates/news-intelligence/tests/fixtures/event_clusters.json`。测试计算 pairwise precision、recall 和 F1，默认发布门槛分别为 0.90、0.85 和 0.87；任一指标未达标时评测失败。

## 数据库迁移

Schema v9 新增 `event_clusters`、`event_cluster_members`、`event_cluster_decisions`、`event_fact_conflicts` 和 `agent_conclusion_reviews`。迁移只新增表和索引，不覆盖 v8 的不可变资讯修订与证据引用。
