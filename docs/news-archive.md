# 可追溯资讯档案与四时间模型

资讯归档将“来源文档”“内容修订”“抓取观测”分开保存。来源文档由来源编号与规范网址稳定标识；正文事实发生变化时新增不可变修订，并通过 `supersedes_revision_id` 指向上一版，而不是覆盖历史证据。重复抓取相同内容只新增观测，不重复生成修订。

每个修订独立保存事件发生时间、来源发布时间、系统首次发现时间和内容修订时间。所有来源时间同时保存标准 UTC 秒与原始时区文本。按任意时间轴回放时，系统都要求“首次发现时间”和“修订时间”不晚于回测截点，避免用当时尚未看到的旧闻或后续更正穿越回测。

## 许可与原始证据

普通聚合快讯默认只保存元数据与许可范围内的事实摘要。一手公开披露允许保存不超过 2 MiB 的原始来源行，使用 gzip 压缩；正常列表与 Agent 工具从不自动返回原始快照。解析失败也会保存经过大小限制的原始证据、错误类别和抓取观测，便于以后用新解析器重放。

每条记录保存来源、许可、内容类型、语言、解析器版本、SHA-256 内容哈希、HTTP 状态、ETag、Last-Modified、延迟和解析状态；当前未提供响应头的上游保留空值，不伪造。端点进入诊断表前移除查询参数，避免泄露凭证。

## Agent 追溯

标准化资讯条目携带 `document_revision_id`。Agent 完成报告时会把工具结果中的精确修订号写入 `agent_evidence_refs`，形成任务/最终结论到不可变修订的引用；后续更正不会静默改变旧报告使用的证据。

## 保留、恢复与导出

SQLite 使用外键、WAL 和繁忙等待，所有归档 upsert 在事务中串行提交。应用重启后可查询最新文档、完整修订链、来源最近成功状态和准确陈旧年龄。单条 gzip 快照损坏只会使该快照读取失败，文档元数据、其他修订和数据库完整性诊断仍可使用。

自动清理只删除达到保留期的原始快照和抓取观测，不删除不可变修订元数据、哈希与 Agent 引用。归档可导出为 gzip JSON Lines；默认不包含原始快照，只有显式选择才包含，并拒绝覆盖已有目标文件。

测试覆盖迁移幂等、32 路并发写入、内容修订链、重复抓取、四时间回放、重启恢复、Agent 证据引用、单条快照损坏、500 条批量压缩导出和清理后元数据保留。
