# Agent 协议与恢复

## 身份与通道

`conversation_id` 表示稳定会话，`run_id/task_id` 表示一次用户轮次。`agent_ask` 接收由前端预先创建的 Tauri v2 Channel，因此最早事件不会落在订阅之前。每个 envelope 有单调 `seq`，前端拒绝同一 run 的重复/倒序事件。

## MiniMax M3 工具协议

一次 assistant `tool_calls` 后，历史中必须为每个 call id 保留恰好一个 `role=tool` 结果。完整 assistant provider content（包括 OpenAI 兼容模式中的 `<think>`）原样持久化并回传给模型；UI 在流式和历史渲染时剥离私有推理。

应用退出可能发生在 assistant 已持久化、部分工具尚未返回之间。恢复前 `reconcile_tool_history` 会：

1. 规范化缺失或重复 call id；
2. 保留已完成且匹配的结果；
3. 为未完成调用插入明确的 `interrupted=true` 工具结果；
4. 丢弃孤立、重复或不匹配的工具结果。

修复在每次请求前作为协议防火墙运行：工具调用 ID 在整个提交历史中必须全局唯一，缺失、非法、同批重复或跨轮复用的 ID 会被确定性重命名，并同步更新对应结果；孤立或重复结果被丢弃，缺失结果补入明确的中断说明。最终还会校验每个 assistant 调用后是否按顺序紧跟且仅跟一个同 ID 的 tool 结果。校验未通过时在本地停止，绝不把必然触发 MiniMax 2013 的历史发给上游。

## 生命周期与进度

运行事件包含 preparing、reasoning、tools、reviewing、synthesizing 阶段、模型轮次安全上限和可确定的批次完成量。每个工具展示中文名称、参数摘要、批次位置、已耗时、预估时间、来源、时间、成功/失败和证据键。预估时间只用于界面说明，不是 deadline；工具以受控并发的异步 Future 在后台运行，直到完成、上游明确失败或用户主动取消。超过预估时继续显示心跳，不再因固定 45/60/180 秒时限自动降级。切换页面不会丢失会话和进度。

任务在额度错误 2056 时持久化为 suspended。已取得额度重置时间且用户开启“额度恢复后自动继续”时，应用会等待到重置窗口并以有上限的指数退避恢复；未知重置时间则保留手动继续。应用重启后，存储中 status=running 但没有 live handle 的任务在 UI 显示为 interrupted，可以从持久化状态继续。

## 上下文压缩

超过字符预算时，不调用额外模型，而是确定性生成“工作状态快照”：目标、已完成工具及参数、缓存键、证据来源、当前轮次和继续指令。系统提示与最近消息原样保留，工具调用/结果对不拆分，重复压缩不嵌套。

## 用户澄清与选择卡片

计划模式缺少会改变研究路线的关键信息时，Agent 使用 `astock-questions` JSON 围栏表达一至三个问题。问题支持单选、多选、推荐项和自由补充；前端将其渲染为持久化选择卡片，并进入“等待回答”状态。该状态暂停普通输入、快捷问题、追问队列、模型、工具和专家调用；用户完成每个问题并统一提交后，回答才作为同一 `conversation_id` 的下一条用户消息继续研究。“新对话”仍可用于主动放弃本轮澄清。

澄清消息是用户输入边界，不进入多专家复核，也不会触发内部草稿的 `TextReset`。为兼容旧会话和模型偶发偏离，前端也会把带问号的编号问题及其二至六个 Markdown 选项安全转换为选择卡片；普通研究列表不会被误判。未提交的选择随 Agent 会话存入本地状态，切换页面后仍保留；历史中已有后续用户回答的卡片显示为“已回答”。

等待选择时研究报告的校验状态固定为 `not_applicable`，不会把提问前的说明文字抽取成投资结论，也不会显示红色的“校验失败”。用户提交选择、Agent 真正形成结论后才进入证据发布门禁。

## 模型路由与多专家复核

设置页通过 MiniMax `GET /v1/models` 动态发现当前模型，同时允许填写未来模型 ID。快速、深度、最大和计划模式分别路由到可配置的协调、快速、深度与复核模型。

深度任务可并发启动证据、风险、量化、政策事件等独立专家。专家只接收脱敏研究包且不能调用工具，主分析 Agent 保留唯一工具权限并负责综合最终结论。专家评审前的内部草稿不进入用户可见历史。

## 研究与策略执行边界

联网研究分为财经快讯聚合、MiniMax 官方搜索和固定模板聚宽调研。`search_web` 的标题与摘要固定标为 `discovery_only`，只用于发现 URL；引用前必须通过 `fetch_source_document` 读取原始 HTML、JSON、PDF 或正式附件，必要时用 `read_document` 下钻不可变版本的页码/段落。字段冲突由 `compare_source_evidence` 并列保留原值、单位、时点和位置。若搜索后没有一级来源版本，最终回答会被确定性追加“一级来源原文未核验”，搜索摘要不得标为【事实】。Agent 最终结论引用的 `source_version_id`/`fact_id` 会单独持久化，供后续修订审计。

`research_news` 使用统一交易日历和四时钟分类器，仅注入目标交易会话的有界资讯上下文。15:00 后、休市日和收盘后海外事件自动进入下一交易日；仅日期和缺失发布时间采用保守口径。`effective_session.can_increase_confidence=false` 的 stale、未核验、聚合线索或旧闻只能用于继续核验/历史解释，不能提高仓位或结论置信度。事件回测调用同一个分类器并以 `first_seen/revision_time` 阻止未来信息倒灌。

财经新闻关键词按空格和中英文标点拆成多个检索词，任一词命中即可保留，避免把自然语言整句误作精确短语。来源参数同时接受稳定标识、常见简称和中文名称（例如“财联社、金十、华尔街见闻”）；无法识别的单项会留下诊断并被跳过，全部无法识别时回退默认来源，不再中断整场分析。最终条数是整个来源的预算，频道抓取只做有界过采样并在归档前截断，不能把 15 条需求放大成每个频道各 15 条。

多来源按各自限频、重试和熔断策略并行读取；后台任务没有总运行时限，但每次上游访问默认最多等待 30 秒，永久不返回的来源会重试并最终释放并发槽。HTTP 4xx/WAF 拒绝不会盲目重试。进度事件持续公开访问频率等待、并发槽等待、当前尝试次数、已收到的上游记录数，以及证据归档、事件聚类和实体关联的逐批进度。部分频道失败会和成功内容一起返回；全部来源不可用时工具返回 `degraded` 的结构化诊断、来源健康状态和已处理记录数，让主 Agent 继续使用其他证据。

AI 生成策略使用版本化公式 DSL，仅能读取当前及历史 OHLCV、有限指标和布尔条件；限制表达式深度、节点、窗口与偏移，不执行任意 Lua、Python、文件、网络或进程操作。聚宽能力同样使用固定查询模板，不接受模型生成的任意 Python。

## 结构化报告与发布门禁

每个成功工具快照会生成稳定的 `evidence_id`，压缩摘要中的标量字段另外生成 `evf_*` 字段证据编号，并记录 JSON 字段路径、原始值、单位、币种、来源等级、数据时间、新鲜度、质量阻断状态、工具版本与内容寻址的数据版本。确定性引擎输出还带有 `calc_*` 计算编号。模型只能引用这些已存在编号，不能自行创建引用。

最终回答同时组装为 `astock-research-report/v1`：每条关键结论具有 `claim_type`、`evidence_ids`、`calculation_ids`、`as_of`、`confidence`、`assumptions`、`counter_evidence`、`invalidation` 与 `unknowns`。模型完成后，由不调用模型的 Rust 校验器独立检查：

1. 证据和计算编号是否存在；
2. 金额、百分比、日期、证券代码和目标价能否从所引字段复现；
3. 单位、币种、价格实时性和来源等级是否合格；
4. 是否存在未解决冲突、质量阻断或无依据的绝对化表述。

合理格式换算（例如 `200000000` 与 `2亿元`、比率与百分数）允许通过，但不允许改变原始含义。首次失败后，编排器把具体错误交给模型进行不带工具的证据内修订，最多两次；仍失败时丢弃用户可见草稿，只发布“报告未通过证据校验”的安全说明，任务状态为 `verification_failed`。被阻断报告仍保存原结论结构和逐条错误，便于诊断，不会伪装成正常完成。

用户明确提供的资金、期限和偏好只能标为 `assumption`/`unknown`，可以原样保留但不能伪装成外部事实；这两类约束不做“必须能从行情证据复现”的数字校验。事实、计算和推断仍执行完整数字与证据校验。

报告在完成事件前写入 `reports`，内容同时包含完整结构化报告、校验结果、工具版本映射和数据版本映射。界面的“结论与证据校验”可逐层展开到字段原值、路径、来源、时间、缓存键和错误，并可复制单项或完整诊断记录。

## 安全边界

Agent 只能产出研究结论、回测结果和人工方案，不具备券商登录、订单提交或自动交易工具。重要数字必须来自确定性工具，最终报告保留证据来源和时间；多 Agent 一致也不等同于事实成立或未来收益保证。

所有工具结果统一附带 `data_quality`，包含数据集、年龄、实时性、质量标记、置信上限及是否允许确定性计算。缓存命中按当前时间重新计算实时性。硬过期、口径不兼容和跨源冲突由编排器在最终输出前再次扫描并追加不可绕过的阻断声明；陈旧、缺失或未跨源复核会自动降低置信度。详细契约见 `docs/data-quality.md`。
