# Agent Runtime 加固

本文记录 AStock Terminal 智能助手的运行时恢复、流式协议、工具缓存和防卡死约束。目标不是让所有上游请求都成功，而是确保任何单点故障都能被明确观察、有限重试、持久化恢复，并最终进入可诊断终态。

## 运行时分层

### 1. MiniMax 流式事务边界

模型流在首次产生用户可见文本、工具调用或正常结束原因之前，处于 **pre-commit** 状态。

- pre-commit 阶段仅有私有 reasoning chunk 时，连接中断可重新建立请求；旧 reasoning 缓冲会被丢弃，不向上层重复提交。
- 首包持续 90 秒无数据，或相邻 chunk 持续 120 秒无数据，触发空闲看门狗。
- pre-commit 最多完整重建两次请求，并使用有界随机退避。
- 一旦出现用户可见文本、工具调用或结束原因，流进入 **committed** 状态。此后禁止在 provider 层自动重放，避免重复文本和 `tool_call_id` 冲突。
- committed 流异常关闭会返回明确的瞬时错误，由持久化 Agent 监督器处理，而不是将截断内容当作正常回答。
- reasoning 缓冲最多 2 MiB；达到上限后提交给上层保存，防止异常模型无限占用内存。

### 2. 持久化任务监督器

原编排器仍负责每轮消息、工具结果、证据和任务状态的 SQLite 持久化。外层监督器只处理运行时故障：

1. 捕获网络错误、限流、超时、SSE 断流和无终态退出；
2. 向 UI 发送 `TextReset`，清除尚未持久化的流式草稿；
3. 将任务恢复为 `running`，清除临时 `last_error`；
4. 调用原编排器的 `resume_task`，从最近完整轮次重新加载历史；
5. 以 1、2、4 秒退避，最多自动恢复三次。

认证失败、API 协议错误、JSON 解析错误、存储错误、工具历史不变量失败、证据校验失败、取消和超过最大轮数均不会自动重试。

达到自动恢复上限后，任务持久化为 `suspended`，保留最后错误和完整检查点，可从任务列表人工继续，不会被伪装成正常完成。

### 3. 工具 single-flight 与最终防死锁

工具缓存继续使用 SQLite read-through cache。运行时在它外侧增加同进程 single-flight：

- 相同 `(tool, canonical_args)` 同时到达时，只允许一个 leader 执行上游请求；
- 其他调用等待 leader，随后重新读取 SQLite 缓存；
- 不共享可变内存结果，进程重启后仍以持久化缓存为准；
- 不改变工具注册顺序和模型工具 schema，保持提示词前缀稳定。

每类工具另有宽松的最终运行预算。这不是常规超时，而是永久不返回时的最后保护：

| 工具类别 | 最终预算 |
|---|---:|
| 行情、搜索、自选股、缓存下钻 | 90 秒 |
| K 线、指标、资金流、市场宽度 | 180 秒 |
| 个股分析、基本面、估值、比较 | 360 秒 |
| 新闻、网页、公告、全球事件研究 | 600 秒 |
| 全市场扫描、图谱、量化、回测 | 1200 秒 |

触发预算后，该工具返回普通结构化失败；同轮其他工具和主 Agent 继续运行，并在最终报告中标注证据缺口。

## 缓存键规范化

缓存哈希前执行以下确定性转换：

- 删除对象中值为 `null` 的可选字段；
- 裁剪字符串首尾空白；
- `symbol`、`code` 删除内部空白并转为大写；
- 周期别名统一为 `day/week/month/1m/5m/15m/30m/60m`；
- `raw` 和空复权参数统一为 `none`；
- 保留数组顺序，因为候选排序和来源优先级可能具有语义。

规范化只合并当前类型契约中确定等价的输入，不进行模糊语义缓存。

## 故障处理矩阵

| 故障 | provider 层 | Agent 监督器 | 最终行为 |
|---|---|---|---|
| 首包或 chunk 永久静默 | 看门狗转为网络错误 | 从检查点有限恢复 | 成功继续或挂起 |
| reasoning 阶段断流 | pre-commit 安全重建 | 通常无需介入 | 不重复公开输出 |
| 已输出文本后断流 | 禁止 provider 重放 | `TextReset` 后恢复完整轮次 | 不发布截断草稿 |
| HTTP 429 / 临时 5xx | 建连退避；失败后上抛 | 有界整轮恢复 | 成功继续或挂起 |
| HTTP 401/403 认证失败 | 立即失败 | 不自动重试 | 明确失败 |
| 单个数据源 403 | 工具返回失败 | 主循环不终止 | 使用其他证据降级完成 |
| 同参数并发工具调用 | single-flight 合并 | 无需介入 | 一次上游调用，多次缓存读取 |
| 工具永久不返回 | 最终预算取消 future | 主循环继续 | 局部失败，不拖死全场 |
| 应用退出或转发器中断 | 无内存续跑假设 | SQLite 任务显示 interrupted/running | 人工继续 |

## 必须保持的协议不变量

- 每个 assistant tool call 后必须恰有一个同 ID 的 tool result。
- 只有完整结束的模型轮次才能写入对话历史。
- 未持久化的流式草稿在重试前必须清空。
- provider 层只能在 pre-commit 阶段重建请求。
- 自动恢复必须有次数上限；达到上限后任务仍可人工继续。
- 工具失败不得阻止同批其他工具完成。
- 缓存命中后仍按当前时间重新计算数据新鲜度与质量门禁。
- `Completed` 只能由报告持久化和独立证据校验之后发出。

## 回归测试重点

- 首包超时、reasoning-only 断流和 committed 断流；
- SSE 无结束标记、连接异常关闭和恢复次数耗尽；
- transient 与 hard error 分类；
- 16 个相同工具请求只执行一次上游调用；
- 缓存参数别名与数组顺序；
- 工具永久 pending 后释放并发槽；
- 恢复后不重复 assistant/tool 消息；
- quota suspension 与 runtime recovery 不相互误判；
- UI 收到 `TextReset` 后不保留截断回答。
